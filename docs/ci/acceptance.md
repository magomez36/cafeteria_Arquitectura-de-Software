## Commit-range timing

The commit-range validator keeps the SC-001 budget of 15 minutes for a typical pull request of up to 10 commits. For larger histories, the budget scales by another 15 minutes per additional block of 10 commits; every commit still receives its configured checks. Run `43971522418` completed all 26 commit validations successfully in 914,962 ms, but the validator incorrectly applied the fixed 15-minute typical-PR limit to the entire larger history. The current correction scales that budget without changing any quality checks.

## Controlled negative test procedure

Run negative cases only in a private disposable branch/PR, never in `main`, `feature/spec-1`, a release tag, or a production environment. Use a synthetic non-secret Gitleaks fixture and a pinned known-vulnerable test package/image that is excluded from production manifests. Capture the job/check name, failing step, conclusion, and remediation. Remove each fixture with a follow-up commit and confirm the cleanup PR run is green. For the coverage case, confirm Sonar reports a numeric failing gate rather than `not-computed`; missing credentials or a missing analysis are infrastructure failures, not a negative coverage result.

Sonar analysis run `43917776461` computed a failed gate: 23.0% new-code coverage, C security rating, and D reliability rating. CodeQL, dependency audit, secret scan, and API/worker Trivy scans passed in that run. Run `43968734209` was cancelled at the 15-minute job timeout before LCOV/Sonar; run `43971522418` completed the 26-commit validator successfully but failed its fixed duration guard before Sonar. The next run must confirm LCOV import and a computed Quality Gate. This file does not claim that pending negative GitHub scenarios have been run.
